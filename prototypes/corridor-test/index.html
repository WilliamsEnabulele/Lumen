What this rig is for

  • It tests one assumption: that a script plus a resume pointer feels like being taught, rather than like a synthesised voice reading at you with a search box bolted on. Interrupt it. Then notice whether you want to interrupt it again — that, not the latency, is the result.
  • The resume pointer is three-dimensional here — script node, character offset inside the utterance, and canvas state — because restoring the speech but not the diagram is still a wrong resume. Watch the pointer panel while you interrupt.
  • False positives are handled, not avoided. Stopping instantly on any voice means sometimes stopping for a cough. If nothing intelligible arrives within 1.2 s it resumes mid-utterance from the stored offset, and logs it.
  • Answers cite their source node. Nothing is generated: every answer is matched from this lesson's own content, and anything unmatched is declared out of scope rather than guessed at.

What it deliberately isn't

  • No LLM and no realtime voice provider. It uses the browser's own speechSynthesis and SpeechRecognition, so the voice is worse than the product's would be and the Q&A is keyword-matched. Both are the point: if the experience works on this, the assumption survives; a better voice can only help it.
  • The latency number is partial. It measures detection → synthesis cancelled, which excludes the OS audio buffer drain that a real client would also have to cap. Treat it as a floor, not the NFR-1 measurement.
  • One 5-minute lesson, hand-written, not ingested. The dimensioning doc asks for 15; this is the short cut of it.
  • Chrome and Edge only for the speech-recognition path. Everywhere else, type the interruption or press space — everything except live ASR still works.
